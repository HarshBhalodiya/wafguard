PHASE 1 (P0) — Foundation: data model + synthetic generator + event timeline
1A. Manufacturing data model

Create typed schemas (Pydantic) and Mongo collections for:

Lot, Wafer, Equipment, Chamber, Recipe, ProcessParameter
SensorTelemetry (time-series, per wafer/step/chamber)
Defect, WaferMap, MaintenanceEvent, ElectricalTestResult
Keep proper IDs and links (Lot → Wafer → Step → Chamber → Equipment).
Add indexes. Add a simple migration/seed script.
1B. Realistic synthetic generator

Generate at least 5,000 lots (configurable), many equipment and chambers, many recipes. Must include:

Time-series sensors per run: pressure, temperature, RF power, gas flow, vibration (at least 5), at fixed sample rate.
Normal runs and failure scenarios, each with a hidden ground-truth label saved separately:
chamber pressure instability
RF power drift
sensor drift (slow bias)
equipment degradation (gets worse with time since maintenance)
missing sensors / dropouts / stuck values
recipe transition problems
contamination / particle events
Maintenance events that reset degradation.
Defect patterns linked to causes (e.g. pressure instability → particles → edge/scratch pattern → defect density → yield loss). The link must be in the generator so the evidence graph can be tested later.
Yield + electrical test results that depend on the causes plus noise.
Save the ground-truth cause of every failure in a separate file (data/synthetic/ground_truth.parquet). Models must NEVER read it during training. It is only for evaluation.
Keep a config with the failure rate (default 10–20% low-yield lots) so class imbalance is real.
1C. Manufacturing event timeline

One ordered event stream per lot/equipment: process start/end, parameter excursions, equipment alarms, maintenance, recipe transitions, inspection events. Add an API to query it.

Acceptance: one command builds the dataset; tests check schema validity, no duplicate IDs, sensible ranges, correct failure rate, and that ground truth matches injected faults.

PHASE 2 (P1) — Upgrade the ML
2A. Strong tabular pipeline (keep XGBoost)
raw data → feature engineering → train/val/test → XGBoost → yield + risk
Feature engineering from time series: mean, std, min/max, slope, drift, excursion count, time-outside-limits, plus equipment age, time since maintenance, recipe, chamber history.
Time-aware split (train on past, test on future). No random split. Split by lot, never by wafer (avoid leakage). Write a leakage check test.
Cross-validation (time-series CV).
Hyperparameter search (Optuna or similar, fixed budget).
Class imbalance handling (class weights, and compare with resampling).
Probability calibration (isotonic/Platt), plus reliability plot.
Feature importance (gain + SHAP).
Compare against simple baselines: mean predictor, linear/ridge, logistic regression, random forest. Save a comparison table in reports/tabular_comparison.md.
2B. Temporal sensor model (PyTorch)
Input: sensor sequences (pressure, temperature, RF, gas flow, vibration, ...). Handle missing values with masks.
Output: yield risk, expected yield, and an anomaly embedding vector.
Start with GRU/LSTM. Add a small Temporal Transformer later and compare on the SAME split.
Only keep the Transformer in the product if it beats the GRU on the test set. Otherwise say so in the report.
Also compare against the tabular XGBoost on the same test set. If the temporal model does not help, report that honestly.
Save model + config + metrics. Fixed seeds. Early stopping.
2C. Wafer defect vision upgrade
Keep existing CNN + Grad-CAM.
Add: wafer map → encoder → embedding → classification head, and store embeddings for similarity search.
Compare CNN vs ResNet (or ConvNeXt) vs ViT (small). Experiment only; ship the best one.
Report per-class recall, F1, confusion matrix.
Warn clearly if trained on synthetic maps only.

Acceptance: reports/ contains comparison tables, calibration plots, and confusion matrices. Tests pass.

PHASE 3 (P2) — Root-cause intelligence
3A. Historical lot similarity

3B. Multi-signal root-cause engine

Combine, with clear and documented weights (config file):

model attribution (SHAP)
process deviation
temporal evidence (when in the run did it start)
historical evidence (similar lots)
equipment history (maintenance age, alarms)
defect evidence
spatial evidence (wafer map pattern)

Output per candidate: name, score, and the list of supporting evidence items (each with a source and value). Evaluate against the ground truth from Phase 1: Top-1, Top-3, Top-5, MRR. Compare against the old SHAP+deviation ranking to show whether the new engine is actually better.

3C. Root-cause evidence graph

Edges have a strength and evidence links.

API returns the graph as JSON (nodes/edges). Frontend shows it.
